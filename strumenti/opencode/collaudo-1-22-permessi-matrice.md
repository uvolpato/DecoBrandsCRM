### A1-09 — Manca una prova "matrice dei permessi" su tutte le rotte (BFLA)
- Gravità: P3
- Dove: `app/backend/test/` (nessuna prova elenca le rotte)
- Problema: il guard nega una rotta senza permesso, ma una rotta nuova che scrive con un permesso sbagliato (es. `@Post` con `provvigioni.consulta`) passa tutte le prove. Oggi tutte le rotte sono giuste: la prova serve a tenerle così.
- Scenario: domani `POST /api/liquidazioni/:a/:t/riapri` con `@Richiede('provvigioni.consulta')` → un utente in sola lettura riapre un trimestre, e nessuna prova se ne accorge.
- Correzione puntuale: nuova prova che con `DiscoveryService` + `Reflector` (o con `app.getHttpAdapter().getInstance()._router`) elenca i metodi dei controller. Per ogni rotta non GET controlla che il permesso non sia `*.consulta`, `*.esporta` o `collegato`, salvo un elenco chiuso (`accesso/esci`, `accesso/password`, `accesso/profilo`), e che le rotte `pubblica` siano solo `salute`, `accesso/entra`, `dimenticata`, `reimposta`.
- Prova che la verifica: è la prova stessa (`app/backend/test/permessi.spec.ts`).
- Esecutore: DeepSeek V4 Flash: prova su logica già giusta.
- File toccati: `app/backend/test/permessi.spec.ts` (nuovo)
- Dipende da / correlato a: D-38, D-45

**Nota del pacchetto.** Se la prova trova una rotta che scrive con un permesso da sola lettura, **non** correggere il controller: scrivilo nel resoconto (pacchetto V4).

## Database e prove

Lavora **solo** sul tuo database di prova `decobrands_test_1_22` (il nome contiene `decobrands_test`, come vuole
`app/backend/test/ambiente.ts`, che legge `DATABASE_URL_TEST`). Altri pacchetti della stessa onda lanciano jest
nello stesso momento su database loro: sul database condiviso `decobrands_test` due giri si cancellano i dati a
vicenda (A6-05). Anche la cartella dei documenti di prova va separata: `ambiente.ts` la mette in
`os.tmpdir()`, quindi cambia `TMP`/`TEMP`. In Git Bash, da `app/backend`:

```bash
export DATABASE_URL_TEST="$(grep '^DATABASE_URL' .env | cut -d= -f2- | sed 's#/decobrands_db#/decobrands_test_1_22#')"
node -e "const {Client}=require('pg');const c=new Client({connectionString:process.env.DATABASE_URL_TEST.replace('/decobrands_test_1_22','/postgres')});c.connect().then(()=>c.query('CREATE DATABASE decobrands_test_1_22 OWNER decobrands')).then(()=>console.log('creato')).catch(e=>console.log(e.message)).finally(()=>c.end())"
DATABASE_URL="$DATABASE_URL_TEST" npx prisma migrate deploy
export TMP="$TEMP/decobrands-1-22"; export TEMP="$TMP"; mkdir -p "$TMP"
npx jest test/<file>.spec.ts            # sempre con le variabili sopra nella stessa shell
```

Alla fine cancella il database: lo stesso `node -e` con `DROP DATABASE decobrands_test_1_22`. **Mai** `decobrands_db`, mai il
database `decobrands_test` condiviso, mai Integra (192.168.239.49: non si contatta per nessun motivo).
